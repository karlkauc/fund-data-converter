# Fund Data Converter – notes for Claude

See README.md for layout, commands and deployment.

## Conventions
- **Deploy**: public site = Cloud Run service `fund-data-converter` in project `fund-data-converter`
  (europe-west1): `GCP_PROJECT=fund-data-converter scripts/deploy.sh`. The project is passed explicitly; never
  rely on the gcloud default. The VPS copy (converter.status20.net, `GIT_COMMIT=$(git rev-parse --short HEAD)
  docker compose up -d --build`) is a test instance.
- **API types**: the JSON in `backend/app/service.py` is mirrored by hand in `frontend/src/types.ts`; keep
  them in sync.
- **SPA routes** live in both `backend/app/spa.py` (`ROUTE_META`) and `frontend/src/lib/router.ts` (`ROUTES`,
  `TITLES` with the same titles).
- **Content pages** (`backend/app/content/`) are English only. Internal links must resolve
  (`tests/test_seo.py` checks them). `pages.py`, `render.py` and `template.html` are copies shared with
  ../online_viewer, ../xml-online-viewer and ../odata-online-viewer.
- **Issue codes** (`Issue.code`) have DE/EN texts in `frontend/src/lib/i18n.tsx` (`ISSUES`). A new code needs
  both texts; `params` fills the `{placeholders}`.
- **Mapping changes** go in `backend/app/mapping/rules.py`. A rule needs:
  - a path relative to its context,
  - optionally `when` (condition on the TPT row) plus `when_text` (shown on /mapping),
  - optionally a transform with an inverse.

  Run `pytest tests/test_roundtrip.py` afterwards; it must stay lossless.
- **openfunds mapping**:
  - Static and dynamic fields: `backend/app/mapping/openfunds_rules.py`, with the same `Rule` and path
    syntax; the contexts are `of_fund` and `of_shareclass`.
  - Holdings: `openfunds_holdings.py` (OFPH ⇄ TPT fields, checked by translating back).
  - Templates: `openfunds_templates.json` is generated by `tools/build_openfunds_templates.py`; never edit it
    by hand.
  - Afterwards run `pytest tests/test_openfunds_roundtrip.py`. It covers openfunds → FundsXML → openfunds and
    TPT → openfunds → TPT, and both must stay lossless.
- **Directions**: `DIRECTIONS`/`DEFAULT_TARGET` in `backend/app/service.py` mirror `frontend/src/lib/directions.ts`
  and `Direction` in `types.ts`.
- **XML is never built by hand**: use `Node.set/ensure` and `serialize_at`. The schema model orders children,
  normalises values, drops invalid optional subtrees and reports what was lost.
- **Hand-over** to xml-viewer.online (FundsXML + `/api/schema/fundsxml.zip`) and findatex-validator.eu (TPT):
  `frontend/src/lib/handoff.ts`, window.open + postMessage, nothing stored. `SENDER_ORIGINS` must match the
  allow-lists in `../xml-online-viewer` and `../findatex-validator` (`lib/handoff.ts` in both). Never send
  `Cross-Origin-Opener-Policy: same-origin` from the SPA, or the popup loses its opener.
- **TPT catalogs** (`backend/app/spec/tpt_v7.json`, `tpt_v8.json`) are copied from `../findatex-validator` by
  `tools/sync_specs.py`; never edit them by hand. V8 is the final version of 2026-10-08 (mandatory from the
  end-of-March 2027 production). FundsXML 4.2.11 has no V8 block, so V8 goes into the V7 block plus `TPT_<field>`
  custom attributes until FundsXML 4.2.12 is released. Version fitting (`to_tpt._adapt_version`): a V8 output
  leaves the 18 N/A fields (`Catalog.not_applicable_keys()`) empty; a V7 output of V8 data drops 150/151, maps
  e1/e2/e3 → e and issuer code type 2 → 9. In the V7 block, V8 data gets the V7-only required elements filled
  (`to_fundsxml.V7_BLOCK_FILLERS`). Samples: `tools/make_samples.py` (needs the validator checkout).
- **Dev venv**: Python 3.14 in `.venv`; Docker and CI use 3.12. Code must run on 3.12.
- `frontend/.npmrc` sets `legacy-peer-deps` (vitest 4 and vite 6 peer ranges).
